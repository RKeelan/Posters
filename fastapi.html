Origin scheme + host + port
  • HTTPS protects HTTP with TLS. Default ports: 443 for HTTPS, 80 for HTTP.
  • Query starts with ?; & separates parameters. Percent encoding represents characters such as a space with %20.
  • Origin changes when the scheme, host or port changes.
  • Fragment starts with # and is never sent in the HTTP request.

2. The request–response cycle

  • API — an interface programs use to communicate. A web API exposes operations over HTTP.
  • Client → server — a browser, app or command-line client sends an HTTP request; the server returns a response.
  • Request — method + target path and query + headers + optional body.
  • Response — status code + headers + optional body. FastAPI normally serialises returned dicts and models as JSON.
  • FastAPI — the Python web framework. Uvicorn is an ASGI server that runs the app and handles network connections.
  • Resource — something the API exposes, such as an item. REST is an architectural style; using FastAPI alone does not make an API RESTful.

3. Route, endpoint, handler

  • Endpoint — an operation exposed to clients: an HTTP method + URL path, such as GET /items/{item_id}.
  • Handler — the Python function that processes requests to an endpoint, such as read_item.
  • Route — the registration rule connecting an endpoint to its handler.
  • FastAPI terms — a path operation is the method + path pair; its path operation function is the handler. FastAPI's internal endpoint argument also means the handler.
  • Decorator — @app.get(...) registers the handler. GET /items/42?q=blue calls it with item_id=42 and q="blue".

Minimal application · main.py

from fastapi import FastAPI

app = FastAPI()

@app.get("/items/{item_id}")
def read_item(
    item_id: int, q: str | None = None
):
    return {"id": item_id, "q": q}

4. HTTP methods / verbs

  • GET — read a resource. Safe and idempotent. Use query parameters for filters; avoid request bodies.
  • POST — submit data or create a resource. Generally not idempotent; retries can duplicate work.
  • PUT — create or replace the state at a target URL. Idempotent.
  • PATCH — partially update a resource. Not necessarily idempotent.
  • DELETE — remove a resource. Idempotent, even if a retry returns a different status.
  • HEAD — GET semantics without a response body. OPTIONS — ask about communication options; also used for CORS preflight.
  • Safe means no requested state change. Idempotent means repeating the same request has the same intended server effect as doing it once.
  • Use @app.post, @app.put, @app.patch, etc. You implement the semantics; the decorator does not provide storage or CRUD logic.

5. Parameters and validation

  • Path parameter — item_id appears in {item_id}; always required. The int annotation parses and validates it.
  • Query parameter — a scalar function parameter absent from the path, such as q. A default makes it optional; no default means required.
  • Nullable ≠ optional — str | None permits None; = None lets the caller omit the parameter.
  • Validation — ?limit=abc or ?limit=0 yields 422 by default, before the handler runs.
  • Route order matters: register /users/me before /users/{user_id}, or “me” can match the parameter route.

Constraints with Annotated and Query

from typing import Annotated
from fastapi import Query

@app.get("/items")
def list_items(
    limit: Annotated[int, Query(ge=1, le=100)] = 10,
):
    return {"limit": limit}

6. Request body and schema

  • Body / payload — request content, separate from the URL. Send {"name":"Pen","price":2.5} with Content-Type: application/json.
  • Schema — the data's shape and constraints. Pydantic parses and validates data, and can coerce compatible values.
  • Model instance — item.name accesses a validated field; item.model_dump() produces a Python dict.
  • Response model — validates, serialises and filters the returned data to the declared schema.
  • A Pydantic model parameter is read from the body by default. Use Body() for scalar body values; Form() and File() handle other encodings.

Pydantic model → JSON body

from pydantic import BaseModel, Field

class Item(BaseModel):
    name: str
    price: float = Field(gt=0)

@app.post("/items", status_code=201,
          response_model=Item)
def create_item(item: Item):
    # Echo only; add persistence here.
    return item

7. Headers, cookies and CORS

  • Header — named request or response metadata. Header names are case-insensitive.
  • Content-Type describes the body being sent; Accept states the response media types the client accepts.
  • Authorization: Bearer … carries credentials. Reading the header alone does not authenticate a caller.
  • Cookie — data a browser stores from Set-Cookie and sends in a Cookie header on eligible requests. Use Cookie() to read one.
  • user_agent maps to User-Agent: underscores become hyphens by default.
  • CORS — browser rules for cross-origin access. Configure CORSMiddleware for allowed frontend origins. CORS is not authentication.

Read a header with Header

from fastapi import Header

@app.get("/agent")
def agent(
    user_agent: Annotated[str | None, Header()] = None,
):
    return {"user_agent": user_agent}

8. Status codes and errors

  • 2xx success — 200 OK; 201 Created; 204 No Content (no response body).
  • 3xx redirection — 307 temporary and 308 permanent redirects preserve the request method.
  • 4xx client errors — 400 bad request; 401 missing/invalid authentication; 403 forbidden; 404 not found.
  • 405 method not allowed; 409 conflict; 422 request validation failed; 429 too many requests.
  • 5xx server errors — 500 internal error; 502 bad gateway; 503 service unavailable.

Raise an HTTP error; do not return it

from fastapi import HTTPException

@app.get("/missing")
def missing():
    raise HTTPException(
        status_code=404,
        detail="Item not found"
    )
# JSON response: {"detail": "Item not found"}

9. Running and organising an app

  • Install: python -m pip install "fastapi[standard]". Run locally: fastapi dev main.py.
  • Try it: open http://127.0.0.1:8000/docs for Swagger UI; /redoc is another docs view.
  • OpenAPI — the machine-readable API description at /openapi.json; drives documentation and client generation.
  • APIRouter — groups routes; app.include_router(router, prefix="/v1") adds them to the app.
  • Dependency — Depends(...) asks FastAPI to call a helper and inject its result, such as a database session or authenticated user.
  • Policy — a rule governing API access or behaviour, such as “only admins may delete” or “100 requests per minute”. Dependencies, middleware or an API gateway can enforce it.
  • Middleware — wraps request/response handling, for example to add CORS headers or request timing.
  • async def — use with awaitable I/O. Blocking calls inside it block the event loop. FastAPI runs ordinary def handlers in a thread pool.
  • TestClient — exercises the app in tests without starting a network server.
